# Конфигурация

## Где лежит файл настроек стрима

`stream.config.json` меняется окном «Настройки» или вручную (при закрытом приложении).
Путь к текущему файлу показан внизу окна настроек, там же кнопка «Открыть файл».

| Как запущено | Файл |
|---|---|
| `npm start` из исходников | `client/config/stream.config.json` (личный, git его не отслеживает) |
| `npm start -- --profile=<имя>` (второй экземпляр) | `%APPDATA%\DuoStream-<имя>\stream.config.json` |
| Собранное приложение | `%APPDATA%\DuoStream\stream.config.json` |
| С ключом `--config=<путь>` | указанный файл |

Если файла нет, он создаётся из шаблона `client/config/stream.config.default.json` — только шаблон
попадает в собранный exe. Ошибочные значения при загрузке
заменяются ближайшими допустимыми; при ошибке синтаксиса JSON приложение предупредит и возьмёт значения
по умолчанию.

## stream.config.json

### signaling — подключение к серверу

| Поле | По умолчанию | Описание |
|---|---|---|
| `url` | `ws://127.0.0.1:8787` | Адрес сервера. Стример — `127.0.0.1`, зритель — белый IP стримера |
| `password` | `""` | Общий пароль комнаты = `password` в `server/config.json` |
| `role` | `streamer` | `streamer` или `viewer` |
| `displayName` | `""` | Имя, которое увидит собеседник |
| `hostServer` | `true` | Стример: запускать сигнальный сервер внутри приложения (отдельный `server/` не нужен) |
| `serverPort` | `8787` | Порт встроенного сервера (TCP, пробросить на роутере) |

### video — трансляция (действует у стримера)

| Поле | По умолчанию | Описание |
|---|---|---|
| `width`, `height` | `2560`, `1440` | Максимальный размер кадра; источник уменьшается с сохранением пропорций. `0`, `0` — как у источника |
| `frameRate` | `120` | Частота захвата и кодирования (1–120) |
| `captureEngine` | `auto` | `auto` — собственный захват (WGC, до 120 FPS), при любом сбое автоматически Chromium; `chromium` — только встроенный захват Chromium (на Windows 11 24H2+ до ~60 FPS) |
| `bitrateKbps` | `20000` | Потолок битрейта видео, кбит/с. Для 1440p@120 лучше 25000–35000 |
| `minBitrateKbps` | `8000` | Нижняя граница оценки канала. Если реальный канал уже, будут потери — тогда уменьшите |
| `codecs` | `["AV1","H264","VP9"]` | Порядок кодеков (`AV1`, `H264`, `VP9`, `VP8`) |
| `preferHardware` | `true` | Ставить вперёд кодеки с аппаратным энкодером; если кодирование ушло на CPU — пересоздать сессию, затем перейти к следующему кодеку |
| `contentHint` | `motion` | `motion` — игра/видео (держать FPS), `detail`/`text` — рабочий стол (чёткость, низкий FPS) |
| `degradationPreference` | `maintain-framerate` | Что жертвовать при нехватке канала: `maintain-framerate` (разрешение), `maintain-resolution` (FPS), `balanced` |
| `showPreview` | `true` | Показывать стримеру свою трансляцию |

### audio — звук

| Поле | По умолчанию | Описание |
|---|---|---|
| `micDeviceId` | `default` | Микрофон (выбирается в настройках) |
| `outputDeviceId` | `default` | Устройство вывода голоса собеседника и звука стрима |
| `noiseSuppression` | `true` | Шумодав DTLN (ONNX Runtime), работает локально до отправки |
| `echoCancellation` | `true` | Эхоподавление WebRTC; в наушниках можно выключить |
| `autoGainControl` | `true` | Автоусиление микрофона |
| `voiceBitrateKbps` | `64` | Битрейт голоса Opus (16–256) |
| `captureSystemAudio` | `false` | Галочка «Передавать системный звук» в окне выбора источника по умолчанию |
| `systemAudioBitrateKbps` | `160` | Битрейт стерео-звука трансляции (32–510) |

### network — сеть

| Поле | По умолчанию | Описание |
|---|---|---|
| `iceServers` | Google STUN ×2 | STUN/TURN-серверы в формате WebRTC `RTCIceServer` |
| `turn.enabled`, `turn.urls`, `turn.username`, `turn.credential` | выкл | Резервный TURN ([04-optional-turn.md](04-optional-turn.md)) |
| `udpPortRange.min`, `.max` | `50000`, `50019` | Диапазон UDP-портов WebRTC; должен совпадать с пробросом на роутере. `0`, `0` — без ограничения (тогда кандидаты для проброса не создаются) |
| `publicIp` | `""` | Белый IP стримера; пусто — определяется по HTTPS-запросу к api.ipify.org (тем же путём, что TCP-подключение зрителя), при неудаче — через STUN. STUN может вернуть чужой адрес, если провайдер или роутер уводит UDP к Google другим маршрутом |
| `forceRelay` | `false` | Только TURN (для проверки релея) |

### playback — воспроизведение (у зрителя)

| Поле | По умолчанию | Описание |
|---|---|---|
| `jitterBufferTargetMs` | `0` | Целевой джиттер-буфер видео, мс. `0` — автоматически (минимальная задержка); 50–150 сглаживают нестабильную сеть ценой задержки |

## server/config.json

| Поле | По умолчанию | Описание |
|---|---|---|
| `host` | `0.0.0.0` | Интерфейс для прослушивания |
| `port` | `8787` | TCP-порт (пробросить на роутере) |
| `password` | `""` | Общий пароль комнаты, от 8 символов. Без него сервер не запустится |
| `maxMessageBytes` | `262144` | Максимальный размер сообщения |
| `heartbeatSeconds` | `15` | Период ping; мёртвые соединения закрываются через 2 периода |
| `authTimeoutSeconds` | `10` | Время на вход после подключения |
| `authFailLimit`, `authBanSeconds` | `5`, `300` | После N неверных паролей IP блокируется на M секунд |

Переменные окружения переопределяют файл: `DUO_HOST`, `DUO_PORT`, `DUO_PASSWORD`, `DUO_CONFIG` (путь к файлу).

## Флаги Chromium (client/src/main/main.js)

| Флаг | Зачем |
|---|---|
| `--enable-features=WebRtcAV1HWEncode` | Аппаратный AV1 в WebRTC; на Windows по умолчанию выключен |
| `--disable-features=WebRtcHideLocalIpsWithMdns` | Реальные локальные IP в ICE-кандидатах (нужно для кандидатов проброшенных портов) |
| `--disable-renderer-backgrounding` и др. | Не замедлять приложение, когда оно свёрнуто, а на экране игра |
| `--force_high_performance_gpu` | Просить дискретную видеокарту на системах с двумя GPU |

## Собственный захват (client/native/capture)

`duostream-capture.exe` запускается главным процессом при старте трансляции и завершается вместе с ней.
Аргументы задаёт приложение: `--parent <pid> --fps <N> (--window <HWND> | --point <x>,<y>) --gpu <vendor>:<device>`.
Протокол обмена (JSON-строки в stdout, команды `free`/`gen` в stdin) описан в начале `Program.cs`.
Текстуры создаются на той видеокарте, на которой работает Chromium (по `vendorId:deviceId` из
`app.getGPUInfo`), иначе их нельзя импортировать.
