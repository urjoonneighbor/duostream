# Установка и запуск с нуля

Роли: **стример** — у него белый IP, на его ПК работают сервер и приложение.
**Зритель** — только приложение, сервер ему не нужен.

## 0. Готовый exe — запуск без консоли

Если у вас есть `DuoStream-Setup-1.0.0.exe` или `DuoStream-1.0.0-portable.exe` (как их собрать — раздел 7),
ничего из разделов 1–6 устанавливать не нужно: Node.js, npm и .NET не требуются, сервер встроен.

- **Установщик** ставит программу и создаёт ярлык DuoStream на рабочем столе и в меню «Пуск».
  **Portable** — один файл, запускается без установки (при каждом запуске распаковывается ~3 с).
- Windows может показать «Система Windows защитила ваш компьютер» (exe без цифровой подписи):
  «Подробнее» → «Выполнить в любом случае».
- При первом запуске Windows спросит доступ к сети для DuoStream — разрешите для **частных и
  общественных** сетей, иначе зритель не подключится. Правила для портов — [02-port-forwarding.md](02-port-forwarding.md).

**Стример:** DuoStream → «Я стример» → галочка «Запустить сигнальный сервер в приложении» (включена)
→ порт 8787 → пароль (от 8 символов) → «Подключиться». Пока зритель не подключился, на экране виден
адрес вида `ws://203.0.113.10:8787` и кнопка «Копировать» — передайте адрес и пароль зрителю.

**Зритель:** DuoStream → «Я зритель» → адрес от стримера, пароль → «Подключиться».

Настройки сохраняются в `%APPDATA%\DuoStream\stream.config.json`, в следующий раз достаточно
нажать «Подключиться». Разделы ниже — для сборки и запуска из исходников.

## 1. Что установить (оба ПК)

| Компонент | Версия | Зачем |
|---|---|---|
| Windows 10/11 x64 | 10 21H2+ / 11 | Захват экрана и звука, Media Foundation |
| [Node.js](https://nodejs.org/) LTS | 20 или новее (проверено на 24) | Сервер, сборка и запуск клиента |
| Драйвер NVIDIA | актуальный Game Ready или Studio | NVENC AV1 (RTX 40xx и новее), декодирование |
| [.NET SDK](https://dotnet.microsoft.com/download/dotnet/10.0) | 10 (только у стримера, только для сборки) | Собственный захват 120 FPS (`duostream-capture.exe`) |

Без .NET SDK приложение работает, но захват экрана идёт через Chromium — до ~60 FPS на Windows 11 24H2+.
Собранному приложению (`npm run dist`) .NET не нужен: exe захвата самодостаточный.

При установке Node.js оставьте галочку «Add to PATH». Проверка в PowerShell:

```powershell
node --version
```

```powershell
npm --version
```

**Ноутбук или ПК с двумя видеокартами** (встроенная + NVIDIA): «Параметры Windows → Система →
Дисплей → Графика» → добавьте `client\node_modules\electron\dist\electron.exe` (а после сборки —
`DuoStream.exe`) → «Высокая производительность». Монитор подключайте к разъёму видеокарты NVIDIA,
а не материнской платы: иначе изображение копируется между видеокартами. Проверить, на какой
видеокарте работает приложение, можно в «Настройки» → «Диагностика» (строка «GPU (используется)»).

## 2. Скопировать проект

Положите папку `duostream` на оба ПК (архивом, флешкой или через git). Дальше команды выполняются
в PowerShell из этой папки.

## 3. Сигнальный сервер (только ПК стримера)

```powershell
cd server
npm install
```

Откройте `server/config.json` и задайте общий пароль комнаты (от 8 символов, его же вводит зритель):

```json
{
  "host": "0.0.0.0",
  "port": 8787,
  "password": "придумайте-длинный-пароль"
}
```

Проверка и запуск:

```powershell
npm test
```

```powershell
npm start
```

В консоли появится `Сигнальный сервер DuoStream слушает 0.0.0.0:8787` и список локальных IP —
нужный пригодится для проброса портов. Окно с сервером не закрывайте, пока идёт стрим.
Пароль можно не хранить в файле: `$env:DUO_PASSWORD="..."; npm start`.

## 4. Приложение (оба ПК)

```powershell
cd client
npm install
```

`npm install` скачивает Electron (~110 МБ), копирует ONNX Runtime в `src/renderer/vendor/ort` и, если
установлен .NET SDK 10, собирает собственный захват в `native/bin/duostream-capture.exe` (первый раз
~1 минута: .NET скачивает свои пакеты). Без .NET SDK будет предупреждение, установка не прервётся.
Собрать захват отдельно (например, после установки .NET SDK):

```powershell
npm run build:native
```

Модели шумодава уже лежат в `src/renderer/models` (`dfn3` — DeepFilterNet3, `dtln` — запасная DTLN). Запуск:

```powershell
npm start
```

Сам Electron (~110 МБ) пакет `electron` скачивает не при `npm install`, а при первом `npm start`.
Если при запуске появляется «Electron failed to install correctly» (Node не достучался до GitHub),
поставьте его скриптом — он скачает Electron через PowerShell и проверит SHA-256:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/ensure-electron.ps1
```

## 5. Первый запуск

**Стример**: «Я стример», сервер `ws://127.0.0.1:8787`, пароль из `server/config.json`, имя →
«Подключиться». Windows спросит доступ к сети для `electron.exe` — разрешите для частных и
общественных сетей. Потом «Начать стрим» → вкладка «Экраны» или «Окна» → клик по источнику.

**Зритель**: «Я зритель», сервер `ws://<белый IP стримера>:8787`, тот же пароль → «Подключиться».
Когда в статусе появится «P2P-соединение установлено», а стример начнёт трансляцию, появится картинка.

Кнопки внизу: микрофон (Ctrl+Shift+M в любой программе, Ctrl+M в окне), звук собеседника
(Ctrl+Shift+D), шумодав, громкость голоса и звука стрима, индикатор качества
(клик — подробная статистика: путь P2P/TURN, пинг, потери, кодек, аппаратно или на CPU, FPS),
полный экран (двойной клик по видео). Шестерёнка вверху — настройки: разрешение, FPS, битрейт,
кодеки, микрофон, шумодав, устройство вывода, сеть; «Клавиши» — глобальные горячие клавиши и режим
рации (push-to-talk); «Диагностика» показывает GPU, поддержку кодеков, клавиши и обновления.

Горячая клавиша, нажатая в игре, подтверждается коротким сигналом: два тона вверх — микрофон включён,
вниз — выключен.

Порты на роутере и белый IP: [02-port-forwarding.md](02-port-forwarding.md), [03-static-ip.md](03-static-ip.md).

## 6. Проверка на одном ПК

Два экземпляра с разными профилями (настройки второго хранятся в `%APPDATA%\DuoStream-viewer`):

```powershell
npm start
```

```powershell
npm run start:viewer
```

В первом окне войдите стримером, во втором — зрителем, оба на `ws://127.0.0.1:8787`.

Оффлайн-проверка шумодава тем же кодом, что в приложении (результат — `client/test-output/*.wav`):

```powershell
npm run test:denoiser
```

Можно передать свою запись голоса (WAV 16-bit или float) и SNR в дБ, модель, предел подавления,
вид шума и голосовой порог: `node scripts/test-denoiser.mjs voice.wav 5 --model=dfn3 --limit=0 --noise=keys --gate`.
Без записи используется синтетический «гудок» — DeepFilterNet3 его справедливо глушит, поэтому тогда
проверяется только подавление шума в паузах.

## Проверка FPS

Откройте статистику (клик по индикатору качества) у стримера:

- «Захват» — `собственный (WGC) · 120 к/с …` значит, работает захват на 120 FPS; `Chromium` — запасной
  встроенный захват (до ~60 FPS). Причина отката показывается во всплывающем уведомлении, а «Настройки» →
  «Диагностика» → «Собственный захват» объясняет, почему он недоступен (например, не собран);
- «Кадр» — фактический FPS после кодирования, «Видео ↑» — кодек и «аппаратно/программно»;
- «Ограничение качества: ширина канала» — WebRTC уменьшает кадр или FPS из-за битрейта: поднимите
  битрейт (для 1440p@120 — 25–35 Мбит/с) или выберите «Держать разрешение».

В «Настройки» → «Видео» → «Способ захвата» можно принудительно выбрать «Только Chromium».

Чего ожидать от встроенного захвата Chromium:

- **Windows 11 24H2 и новее** (сборка 26100+, узнать: `winver`): не больше ~60 FPS. Windows Graphics
  Capture по умолчанию отдаёт кадр не чаще раза в 16 мс и только на границе обновления монитора:
  на 60/120/240 Гц это 60 FPS, на 144 Гц — 48, на 170 Гц — 57. Для экрана 1440p — ещё и ~50 FPS
  из-за правила Chromium «захват не дольше 50% времени ядра». Настройками приложения или Windows
  это не обойти.
- **Windows 10 и Windows 11 до 24H2:** экран Chromium захватывает через DXGI Desktop Duplication,
  ограничения в 16 мс там нет, остаётся только правило 50%. Этот вариант на стенде не проверялся.

Общие рекомендации:

- запускать игру в режиме «окно без рамки» (borderless): эксклюзивный полноэкранный режим
  может давать чёрный кадр или рывки при захвате;
- проверить в «Диагностике», что приложение работает на видеокарте NVIDIA.

## 7. Сборка exe (установщик и portable)

В папке `client` после `npm install`:

```powershell
npm run dist
```

Скрипт `scripts/dist.ps1` собирает захват 120 FPS (нужен .NET SDK 10), скачивает Electron, если
его ещё нет (`npm start` можно не запускать), и инструменты упаковки (7-Zip и NSIS) — через PowerShell
с проверкой SHA-256 (из Node загрузки с GitHub на некоторых сетях обрываются) — и запускает
electron-builder. Результат в `client/dist`:

- `DuoStream-Setup-1.0.0.exe` — установщик с ярлыками на рабочем столе и в «Пуске»;
- `DuoStream-1.0.0-portable.exe` — один файл без установки;
- `win-unpacked\DuoStream.exe` — та же программа в виде папки.

В сборку попадает только `config/stream.config.default.json`. Ваш личный
`config/stream.config.json` с паролем в exe не попадает, и git его не отслеживает.

## 8. Деплой: пуш в master → релиз на GitHub

`.github/workflows/release.yml` на каждый пуш в `master` (или вручную: Actions → Release → Run workflow)
на Windows-машине GitHub ставит Node.js 24 и .NET 10, прогоняет тесты сервера и шумодава, собирает exe
и одним вызовом `gh release create` публикует релиз `v1.0.<номер запуска>` с установщиком, portable-версией
и `latest.yml` (по нему установленные копии находят обновление). Секреты настраивать не нужно —
хватает встроенного `GITHUB_TOKEN`; в настройках репозитория (Settings → Actions → General → Workflow
permissions) должно быть разрешено «Read and write permissions» или хотя бы права, выданные в самом
workflow (`contents: write`).

Установленный DuoStream проверяет релизы при запуске и раз в 4 часа, скачивает новую версию в фоне и
ставит её при выходе (или сразу — кнопкой «Перезапустить сейчас» в уведомлении). Portable-версия
обновляться сама не умеет: она показывает уведомление с кнопкой «Скачать». Отключить — «Настройки» →
«Сеть» → «Проверять обновления на GitHub».

Первый раз установщик из релиза нужно поставить вручную: версии, собранные локально (`1.0.0`), тоже
обновятся сами, только если это установленная (не portable) версия.

Локальный `npm run dist` ничего не публикует.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| «Неверный пароль» | Пароль в приложении = `password` в `server/config.json` (регистр важен) |
| «Сервер недоступен» у зрителя | Сервер запущен; TCP 8787 проброшен; `http://<белый IP>:8787/` открывается с телефона через мобильный интернет |
| Зависло на «Установка P2P-соединения» | Проброшен UDP 50000–50019 на тот же ПК; правило брандмауэра; диапазон в настройках «Сеть» совпадает с роутером |
| «Видео ↑ … программно (CPU)» | Драйвер NVIDIA, «Высокая производительность» для приложения, кодек AV1/H.264 (не VP9) |
| «Собственный захват не запустился …» / FPS ~60 | «Диагностика» → «Собственный захват»; `npm run build:native`; для гибридной графики — «Высокая производительность» (текстуры создаются на той же видеокарте, что и Chromium) |
| Захват окна: картинка обновляется рывками после изменения размера окна | Ожидаемо 1–2 с: Chromium при росте кадра уходит с NVENC на CPU, приложение пересоздаёт сессию |
| «Шумодав: ошибка» | Не выполнен `npm install` (нет `src/renderer/vendor/ort`) или удалены модели — `npm run fetch-models` |
| Не слышно собеседника | Индикатор у ползунка «Голос» (и строка «Голос собеседника» в окне качества соединения) показывает, доходит ли его звук. Индикатор двигается, а звука нет — «Настройки» → «Звук» → «Устройство вывода звука» → «Проверить» и выберите устройство, в котором вы слушаете. Индикатор стоит — у собеседника выключен микрофон или выбран не тот |
| Зритель слышит себя | Включён системный звук: выведите голос собеседника на другое устройство или отключите системный звук |
| «Часы расходятся больше чем на 15 минут» | Включите синхронизацию времени Windows на обоих ПК |
| Нужно посмотреть подробности | F12 в приложении — консоль; объект `duoDebug` содержит состояние, например `duoDebug.session.pc` |
