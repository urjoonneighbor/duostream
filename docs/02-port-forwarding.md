# Проброс портов на роутере стримера

Делается **только у стримера**. Зрителю ничего пробрасывать не нужно, даже за серым NAT.

| Порт | Протокол | Назначение | Где задаётся |
|---|---|---|---|
| 8787 | TCP | Сигнальный сервер (WebSocket) | `server/config.json` → `port` |
| 50000–50019 | UDP | Видео и звук WebRTC (P2P) | настройки приложения → «Сеть» (`network.udpPortRange`) |

Диапазон UDP на роутере и в приложении должен совпадать. 20 портов хватает с запасом: на каждый
сетевой интерфейс ПК WebRTC открывает один сокет.

## 1. Закрепить локальный IP за ПК

Иначе после перезагрузки роутер может выдать ПК другой адрес, и проброс перестанет работать.

1. Узнайте адрес и MAC: `ipconfig /all` → нужный адаптер (Ethernet или Wi-Fi) → «IPv4-адрес»
   (например, `192.168.1.50`) и «Физический адрес» (MAC). Сервер при запуске тоже печатает локальные IP.
2. В веб-интерфейсе роутера найдите DHCP → «Резервирование адресов» (Address Reservation, «Статические
   адреса», «Закрепить IP») и привяжите этот IP к MAC компьютера.

## 2. Создать правила проброса

Общий смысл везде одинаковый: «внешний порт → IP компьютера, тот же порт, протокол».

| Правило | Протокол | Внешний порт | Внутренний IP | Внутренний порт |
|---|---|---|---|---|
| DuoStream signaling | TCP | 8787 | 192.168.1.50 | 8787 |
| DuoStream media | UDP | 50000–50019 | 192.168.1.50 | 50000–50019 |

Где это искать в популярных роутерах (названия пунктов зависят от прошивки):

- **Keenetic**: «Сетевые правила» → «Переадресация» → «Добавить правило»: вход — подключение к
  провайдеру, выход — ваш ПК, протокол TCP или UDP, порт или диапазон портов.
- **TP-Link**: «Дополнительные настройки» → «NAT переадресация» → «Виртуальные серверы» → «Добавить».
  Для диапазона укажите `50000-50019`.
- **ASUS**: «Интернет» → «Переадресация портов» → «Добавить профиль».
- **MikroTik** (замените `ether1` на WAN-интерфейс, при PPPoE это обычно `pppoe-out1`):

```
/ip firewall nat add chain=dstnat in-interface=ether1 protocol=tcp dst-port=8787 action=dst-nat to-addresses=192.168.1.50 to-ports=8787 comment="DuoStream signaling"
/ip firewall nat add chain=dstnat in-interface=ether1 protocol=udp dst-port=50000-50019 action=dst-nat to-addresses=192.168.1.50 comment="DuoStream media"
```

UPnP приложение не использует — правила нужно создать вручную.

**Двойной NAT.** Если перед вашим роутером стоит ещё один (модем или ONT провайдера в режиме роутера),
то на внешнем IP вашего роутера будет серый адрес (`192.168.x.x`, `10.x.x.x`, `100.64–127.x.x`).
Переведите модем провайдера в режим моста (bridge) или повторите проброс на нём — на IP вашего роутера.

## 3. Разрешить порты в брандмауэре Windows

PowerShell **от имени администратора**:

```powershell
New-NetFirewallRule -DisplayName "DuoStream signaling (TCP 8787)" -Direction Inbound -Protocol TCP -LocalPort 8787 -Action Allow -Profile Any
```

```powershell
New-NetFirewallRule -DisplayName "DuoStream media (UDP 50000-50019)" -Direction Inbound -Protocol UDP -LocalPort 50000-50019 -Action Allow -Profile Any
```

Если при первом запуске Windows спрашивала доступ для `node.exe` или `electron.exe` и вы нажали
«Отмена», проверьте «Брандмауэр Защитника Windows → Разрешение взаимодействия с приложениями» —
там не должно быть запрещающих правил для них. Сторонний антивирус с сетевым экраном настраивается так же.

## 4. Проверить

1. Запустите сервер (`npm start` в `server`).
2. С телефона **через мобильный интернет** (Wi-Fi выключен) откройте `http://<белый IP>:8787/`.
   Страница с ошибкой **404** значит, что TCP-проброс работает: сервер ответил, но себя не называет
   (так он не выдаёт себя сканерам). «Не удаётся подключиться» или долгая загрузка — проброс не работает.
   Если в настройках задан список разрешённых IP, телефон в него не входит, и соединение будет сброшено —
   проверяйте до включения списка.
3. UDP браузером не проверить, поэтому подключите зрителя и откройте статистику (клик по индикатору
   качества). Строка «Путь»:
   - `P2P напрямую · host ↔ prflx` или `srflx ↔ …` — всё работает;
   - `через TURN-релей` — прямой путь не сработал, включился резервный TURN (если он настроен);
   - статус так и не стал «P2P-соединение установлено» — проверьте UDP-правило и брандмауэр.

**С самого ПК стримера** белый IP часто не открывается: многие роутеры не умеют NAT loopback.
Поэтому стример подключается к `ws://127.0.0.1:8787`, а не к белому адресу.

## Почему не хватает одного STUN

STUN сообщает стримеру его внешний адрес, но порт, который роутер выдаёт для исходящих пакетов,
может отличаться от проброшенного, а входящие пакеты от незнакомого адреса роутер отбрасывает. Когда
WebRTC ограничен проброшенным диапазоном, порт host-кандидата доступен снаружи напрямую. Приложение
добавляет кандидат `<белый IP>:<этот порт>`, и зритель за любым NAT (включая симметричный CGNAT
мобильных операторов) подключается к нему как к серверу. Белый IP приложение берёт из STUN или из поля
«Белый IP стримера» в настройках «Сеть» — его стоит заполнить, если STUN-серверы недоступны.
